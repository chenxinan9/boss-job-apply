# WorkBuddy 电脑界面版：开发范围与验收

2026-10-15 按用户最新要求收窄。目标为 Windows WorkBuddy + 系统 Edge，以及 macOS WorkBuddy + 系统 Safari；本人明确指定的已安装浏览器可沿用。不安装浏览器，不复制登录状态，不通过换浏览器处理已有验证阻断。

两个独立技能入口放在 `packages/boss-apply-workbuddy-windows/` 与 `packages/boss-apply-workbuddy-macos/`，rc.2 各包含 SKILL.md、DESKTOP.md、一个系统原生准备脚本与 LICENSE。业务流程一致，系统能力说明不同。模型按画面和简历自主判断，保留硬条件、单次沟通、授权和真实停止边界；不自研驱动，不打包数据库、浏览器接入脚本或固定坐标；缺电脑工具时准备固定版本的 Open Computer Use 原生程序。

## 当前能力证据

- 本机 WorkBuddy 5.7.7 随附的 ComputerUse 实现说明为 macOS 桌面截图与鼠标键盘；启用判断包含 `if (!isDarwin()) return false`，还需产品开关。静态实现存在不等于工具已向当前任务开放，更不代表权限已就绪。本次只读查实现，未修改应用或绕过平台判断。
- 这仅是本机 macOS 构建的证据，不能据此声称所有 Windows 版本没有电脑操作功能。Windows 当前版本的实际工具与系统 Edge 尚未实机核对。
- 本机 Codex 原生电脑操作已成功，不等于 WorkBuddy 原生路径成功；此前 WorkBuddy 的 Ego 结果也不能作为这两个候选的成绩。

## 交付门槛

每个系统分别完成：由该系统上的 WorkBuddy 自行取得候选；保留真实个人条件；用实际可用的电脑操作工具观察系统浏览器；本人完成必要登录；选择卡片并读取对应 JD；按授权真实首次沟通后继续处理后续岗位。维护者只观察，不补步骤、代点或改候选工作区。

失败先区分缺工具、权限、窗口选择、读取点击错误和平台验证。缺工具不能靠新增说明或换浏览器掩盖。公开包实际版本与验证版本必须一致；修复后重新验收。首次成功、连续执行与满额分别报告。

## 当前交付状态

两份当前为 v0.4.0-rc.2 未验收预发行候选，供独立实测；不覆盖 v0.3.4 资产，不作为给普通使用者的可用版本推荐。Windows 缺实际测试环境与工具能力证据；macOS 缺 WorkBuddy 原生工具实际调用、Safari 切岗和真实发送证据。仅文件检查通过时不能发布为可用版。

原 Codex 生产流程和个人资料不在本次改动范围；旧浏览器适配代码暂留原位用于已有版本追溯，不再作为这两个候选的后备执行路径。

## 2026-10-15 macOS 独立尝试结果

WorkBuddy 5.7.7 使用用户选定的 Hy3 + Max，自行从公开 Release 下载本 macOS 候选并核对哈希，保留已有个人资料。运行约 5 分 45 秒后结束，报告会话工具检索没有电脑截图、鼠标键盘或系统可访问性控制工具；未进入岗位筛选，首次沟通 0 条、持续投递未开始。本轮没有维护者代点或途中补操作步骤。此结果说明当前会话尚未接通所需工具，不证明所有 WorkBuddy 版本均无该能力。当前候选不可交付为可运行产品。

发布后的 Windows CI 发现测试读取 UTF-8 清单时误用本机默认编码；已在测试显式指定 UTF-8。下载器与技能 ZIP 不受该测试读取问题影响，候选文件及哈希未更换。

## rc.2 接入修复范围

为 rc.1 的缺工具失败补入真正可下载的电脑控制程序，采用上游 Open Computer Use 1.1.0 固定 Release 和 SHA-256。两系统准备脚本只下载、校验、解压和输出连接配置，不注册 MCP、不授予权限、不触碰网页或简历。上游原生二进制提供 MCP 接口，不要求用户安装 Python、Node 或浏览器。

本机官方升级到 WorkBuddy 5.8.2 后，设置显示浏览器操控及扩展入口，仍未显示电脑操控入口；故不以升级本身当作修复成功。选用独立 MCP，不修改产品隐藏开关。Mac 辅助功能和屏幕录制须本人正常授权；Windows 仍须实机验证。原生程序准备、MCP 连接、无外发动作、首次真实沟通和持续执行分开验收。

准备脚本的自动测试使用本地假下载与惰性文件验证错误哈希拒绝、中文空格路径、配置生成、旧目录保护；这是安装代码测试，不是模拟 BOSS 投递。真实站点验收尚未完成，不应将 rc.2 标记为已可交付。
