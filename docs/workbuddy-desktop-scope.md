# 当前候选 v0.4.0-rc.5：官方电脑操控

两个 WorkBuddy 系统包各只有 SKILL.md、DESKTOP.md 和 LICENSE。使用系统已有浏览器，流程与本人资料分离，不安装浏览器、不创建定时、不自建驱动。旧包只保留本人简历和岗位条件，不混用旧执行说明。

本次最小修正来自真实原生界面操作观察：切条件后确认新列表已更新，不能只凭地址或旧卡数；普通加载失败与真实验证分开；必要收起提示后再选下一卡片，自动跳转正常返回。主模型保留匹配判断，官方 GUI 代理按目标观察与操作，create_task 一轮结束后由 continue_task 继续；单个 GUI 任务结束不等于投递任务完成。

## 已实际核对的范围

2026-10-16，维护者的 macOS WorkBuddy 5.8.3 在“设置 → 智能体”未显示电脑操控安装行，但“专家·技能·连接器 → 技能 → 套件 → 添加市场”确实支持 HTTPS ZIP。使用客户端指定的腾讯官方发布清单取得对应归档，校验哈希与腾讯签名后，通过该正常界面添加 workbuddy-computer-use 市场、安装 computer-use；MCP 管理实际显示官方组件已连接，10/10 工具启用，包括 gui_list_windows、create_task、continue_task、read_task 和 gui_screenshot。没有修改隐藏开关或审批记录，旧第三方控制器保持未信任、未启用。

这是安装与注册证据，尚未证明实际窗口读取、系统权限、真实发送或持续执行。主模型免费倍率不代替电脑操控自身的费用提示，额外费用和权限按本人明确授权处理。

Windows x64 官方归档已按清单下载并校验，未在 Windows 实机调用。不能以 macOS、CI 或安装成功替代 Windows 验收，也不把维护者原 Codex 流程的成功算作本公开包的成绩。

## 交付门槛

各系统分别由 WorkBuddy 自行取得公开候选，保留真实个人要求，用实际工具观察目标窗口、核实当前 JD，按本人授权真实首次沟通后继续后续岗位。维护者只观察，不途中代点、补点击步骤或手改候选工作区。首次真实发送、连续执行与平台当天满额分别报告，派发数不冒充成功数；跨日不累计。

本候选仍未通过完整独立实站验收，暂不向非技术使用者推荐为可用版。历史 rc.1–rc.3 的第三方准备和 rc.4 的缺工具尝试均未真实发送；旧方案不作当前后备，详细旧过程保留在版本历史中。失败要先分清工具未注册、权限、窗口、读取点击、普通加载与真实验证，不能反复要求本人登录来代替诊断。
