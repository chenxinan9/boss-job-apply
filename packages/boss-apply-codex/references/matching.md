# 根据自己的资料判断岗位

本项目不预设任何人的城市、职位方向、薪资、招聘来源偏好、工作年限或职业能力。`private/policy.json` 是本人确认的条件，`private/resume.md` 是本人真实经历。模板为空；不能直接进入投递。

## 初始化条件

客户端先根据本人明确提供的简历和需求草拟配置，列出城市、推荐标签、薪资筛选、搜索关键词、允许招聘来源、允许工作范围、排除项、评分维度/权重与通过门槛。本人核对后才将 requirements_confirmed 设为 true。若目标或经历缺失，询问本人，不参考作者背景、不扫描其他私人文件填空。

schema_version=2。review 允许空白草稿，仅用于准备；apply 要求本人条件齐全、确认并明确授权。配置文件本身不构成外发授权。旧版配置不能自动升级成已确认配置。

## 前置条件

按配置检查城市、页面公开薪资、招聘者类型、公司/职位/实际主责排除项和 allowed_scope。允许来源填写当前平台可识别的类型，未知来源跳过；公开包没有预选某一类招聘者。

recommendation_tabs 必须来自本人真实推荐/求职意向入口；salary_bands 必须与当前平台实际筛选档一致，不推测档位。monthly_salary_upper_min_k 为 null 表示无额外月薪上限要求；设值后要求当前岗位公开月薪上限达到该值。不把年薪或奖金臆测成月薪。

任何硬排除优先于分数。实际职责优先于岗位标题；名称类似不等于做同样的工作。

## 自定义评分

没有固定五维、职业专属维度或特殊岗位默认加分。scoring.dimensions 是对象列表，每项包含 id、label、criterion、max_score；由本人确认适合自己的维度，权重合计100。城市与薪资作为前置条件不重复计分。

AI 只根据当前 JD 和本人简历事实给每项 0 到 max_score 的整数分：没有相关事实不给分，间接迁移证据与直接经历区分，覆盖越充分分数越高。同一事实不能在含义重复的维度里反复加分，不能为了达标编造经验。

默认门槛使用 scoring.default.operator（> 或 >=）及 threshold。特殊条件可在 scoring.special_rules 中自行增加，每项包含 name、scope、operator、threshold；scope 必须说明如何根据当前 JD 判定，不能凭标题中的一个词推断。命中特殊规则时采用其门槛，多项同时命中则都须满足；没有命中则用默认门槛。公开模板 special_rules 为空。

评分只在当前上下文用于判断，不建立逐岗文件、历史台账或旧评分引擎。
