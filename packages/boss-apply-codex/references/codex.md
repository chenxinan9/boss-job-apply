# Codex 接入

本包用于 Codex 桌面端；纯 CLI 若没有浏览器/电脑工具，不能声称可以直接执行 UI 投递。

首次先读 [本机接入向导](setup.md)，按实际能力选择工具；原验证路径不构成固定依赖。再读 [浏览器接入与有限恢复](browser-session.md)，它规定本任务可以采用的接入和恢复方式。

## 安装与首次运行

1. 解压 Codex 包。可以将整个 boss-apply-codex 文件夹放入本人 Codex 技能目录，或把解压目录设为工作区，明确要求读取 SKILL.md。当前技能目录由本机 Codex 配置决定，常见为 ~/.codex/skills/；安装后检查当前可用技能列表，不凭文件复制成功宣布已加载。
2. 复制模板为工作区 private/policy.json 和 private/resume.md，填写自己的条件与真实简历。默认 review，定时关闭。配置与简历留在自己的本地工作区，不跟随技能上传。
3. 读取当前 Codex 可用电脑/浏览器工具的说明。原稳定路径为 macOS Chrome 的原生电脑操作与完整可访问性快照。优先复用本人当前已登录的真实 BOSS 列表，不主动改用另一独立浏览器。
4. 如果当前使用 cua_repl，按工具当前文档选择应用并读取状态；只用文档公开的 API，不复制过期调用签名。索引只在产生它的新鲜快照中有效，滚动、切卡、关弹层后要重新读取。
5. 先 review 验证卡片与同页 JD 对应；本人授权后 apply。Windows 可使用当前客户端实际支持的浏览器工具按相同流程操作，本包不提供平台驱动；仅有CLI或缺少实际UI工具时先报告能力缺项。

## 定时与续跑

仅当本人明确要求定时，才在当前 Codex 桌面自动化功能中选择本人工作区，设置自己的时区与每日时间，使用 templates/schedule-prompt.md。在支持同一任务定时跟进的版本中，优先沿用固定执行任务；不要每次同时开启多个worker，不默认设置运行截止。定时操作应调用当前产品提供的管理工具或 UI，JSON 本身不会创建计划。

保存后检查实际任务、下一次触发时间和暂停要求，再启用 private/policy.json 的 schedule.enabled。电脑/客户端/所需会话保持可用，凭真实运行结果判断执行，不将“保存成功”当成当天满额。

故障只能恢复当前任务；正常执行无需监督重复催促。不因安装创建监督任务。用户暂停时也停掉催执行的跟进。
