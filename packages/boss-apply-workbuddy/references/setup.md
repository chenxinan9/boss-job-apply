# 首次接入：按本机能力选择，不绑定作者环境

本页供 Codex 和 WorkBuddy 共用。目标是让当前 AI 完成接入；使用者只需要提供自己的简历、条件和必要的本人登录操作。最新版客户端也可能没有安装浏览器技能，不能据版本号判定已接通。

## 1. 识别环境与选择工具

**先复用当前正常会话。下表的市场/安装分支只适用于没有可用工具的情况，不能覆盖已有的原生或 Ego 会话。**

先看当前客户端实际暴露的工具及其文档，识别操作系统、可用浏览器能力，并发现本人已有的相关窗口/会话。新任务没有保存会话编号，不代表没有可复用浏览器。不要扫描个人磁盘、读取 Cookie 或连接猜测的调试端口。

有 Python 时可运行包内只读检测：

```sh
python3 scripts/doctor.py --client codex
```

Windows 有 Python Launcher 时用 `py -3 scripts/doctor.py --client workbuddy`。客户端参数按实际软件替换；没有 Python 就由 AI 按下面表格检查，Python 不是投递依赖。检测不启动浏览器、不安装软件、不读个人文件、不写报告。

若实际工具清单有原生浏览器/电脑控制，追加 `--tool native`；有 Ego 或 Agent Browser 工具，分别追加 `--tool ego` / `--tool agent-browser`。已有当前任务会话时用 `--existing-session` 指定其工具。不要为得到“通过”而填未安装的能力。输出 ENVIRONMENT_ONLY 只用于选择下一步，不代表浏览器就绪或外发授权。

| 检测结果/情况 | AI 接下来执行 |
| --- | --- |
| CHECK_EXISTING_SESSION | 读取所选工具当前说明，复用当前会话并做下面的页面检查 |
| RECONNECT_EXISTING_TOOL | 恢复原工具连接，保留浏览器；不能在运行途中悄悄换工具或另开执行者 |
| DISCOVER_EXISTING_SESSIONS | 先按工具文档列出已有窗口/会话并核对目标，不能直接创建新浏览器；具体步骤见下节 |
| CHECK_SKILLHUB_AGENT_BROWSER | WorkBuddy 先在自身技能市场检查官方文档介绍的 Agent Browser；已有就启用并读其说明，无此入口再按第 2 节处理 |
| INSTALL_OPTIONAL_AGENT_BROWSER | 没有现成工具时，按第 2 节安装官方浏览器工具 |
| CONNECT_CLIENT_BROWSER_OR_SETUP_OPTIONAL_TOOL | 优先启用客户端支持的浏览器/电脑工具；确实没有再按第 2 节补环境 |

确认没有可复用会话后，才按工具文档创建一次。工具优先级为当前客户端原生工具，其次已经安装且可用的 Ego 或 Agent Browser。用户明确选择的可用工具优先；工具选定后保持不变。若当前宿主限制只能使用指定浏览器工具，遵守宿主限制。未知操作系统需查供应商支持列表，不将“检测成功”当作支持。

### 新任务先发现已有窗口

1. 读取所选工具当前的会话/窗口发现说明，实际列出可用会话，再根据当前标题、URL、本人指定窗口和控制权识别目标。Ego 按当前 `references/api.md` 的 `listTaskSpaces()`、空间页面列表与控制权规则执行；原生工具使用其窗口/标签枚举；其他工具只用其文档支持的发现能力。不能复制这里没有提供的固定编号，也不猜 API。
2. 已有本人 BOSS 页面且没有其他执行者时，按工具的接管/本人交还流程复用，先读取原页，不为了“初始化”重新导航。其他执行者持有控制权时不抢占；有多个候选不能确定时让本人选择。工具无法发现或连接本人所指窗口时说明能力缺口，不能把未查到当成不存在。
3. 只有已确认没有可复用目标、工具确实不支持连接，或本人明确要求隔离新会话时，才建立新会话并说明原因。新工作区、新下载包、旧配置禁用，都不是必须新建浏览器的理由。

### 先选目标，再处理控制权

不能按空间编号大小、名称含“validation”、创建时间或“当前归 Agent 控制”选目标。先匹配本人明确指向的已有窗口；多个相关空间且无法确定目标时，报告候选名称并请本人选定，不能自行取第一个可读窗口。选择过程不得批量 `taskSpace(id)` 试遍候选：这会把控制权暂停混进页面读取。

Ego 先单独调用 `listTaskSpaces()`，保留其实际返回的 ownership。目标明确后，对照当前 Ego 技能说明只处理该目标：

| 目标状态 | 动作 |
| --- | --- |
| Agent 正常控制且没有其他执行者 | 使用发现的编号复用，读取当前页面 |
| `agentDelegatedToUser`：此前交还本人 | 本人在交还后已明确要求继续/重新运行，并同意接管此目标时，使用文档化 `takeOverTaskSpace`；缺此授权就只请求交回控制权 |
| user-owned / inactive | 本人明确授权后按当前工具文档 `claimTaskSpace`；不能把普通读取请求当成接管授权 |
| 本轮执行中再次提示用户接管 / hard stop | 立即停止浏览器命令，等待该提示之后本人的继续指令；此前启动授权不能覆盖新的暂停 |
| 目标归属或控制状态不明 | 不尝试接管，说明需确认的目标或控制权 |

控制权暂停不是 BOSS 安全验证。不能捕获 hard stop 后继续循环、换到另一个可读空间，或把错误吞掉后继续页面检查。接管成功后才读取目标原页，核对标题、URL、可见验证控件和岗位信息；不要重新导航。目标页面真实存在验证时仍交本人处理，不用切窗口规避验证。本人指向的目标无法选择时，这一阶段就是未通过，不得用另一窗口的“两次读取成功”替代。

**配置隔离不等于浏览器隔离。**“不用旧配置/作者项目”禁止带入旧简历、岗位条件、脚本和执行者，不禁止在当前工具支持范围内复用本人已登录的浏览器。正常接管现有会话不是复制 Cookie，也不是复用旧业务配置。

## 2. 没有浏览器工具时的官方补齐路径

**WorkBuddy：**先使用其技能市场的 Agent Browser 接入。若当前版本没有对应入口，或者是没有内置浏览器的 Codex 环境，才使用下列可选 CLI 路径。不要另外生成 apply.cjs、裸 CDP 驱动或绑定某个 Edge 调试端口。

有 npm 且当前客户端允许终端浏览器工具时，按 [Agent Browser 官方安装说明](https://agent-browser.dev/installation) 安装：

```sh
npm install -g agent-browser
agent-browser install
agent-browser --version
agent-browser --help
```

逐条检查退出结果；不要忽略前一步失败继续。第一条安装工具，第二条下载它支持的浏览器，两者不是同一件事。已经安装的不重复装。缺 npm 时，优先客户端现有工具；确实需要 CLI 才从 [Node.js 官方下载](https://nodejs.org/en/download) 安装受支持运行环境，再重开客户端使 PATH 生效。权限要求按当前电脑处理，不关闭系统保护、不使用未知镜像或额外安装数据库服务。

Windows 用 PowerShell，macOS/Linux 用当前 shell；让客户端生成符合本机的参数，不复制别人的绝对路径。当前工具若支持 `agent-browser skills get core --full`，读取随版本提供的操作说明，否则查该版本官方文档。不假设 Playwright API、Ego API 和 Agent Browser 命令可以互换。

安装与配置必须在用户请求的接入范围内执行；已有工具无需再征求安装许可。需要管理员权限、下载被阻断或宿主工具不允许该路径时，具体报告缺哪项、已完成什么、下一步由谁操作，不能声称已运行。

### Agent Browser 会话约定

按照 [官方会话说明](https://agent-browser.dev/sessions)，为自己的工作区选择稳定会话名，并把独立浏览器 profile 放在自己的 `private/browser-profile/`。`--profile` 必须传该目录的**本机绝对路径**，不用 `Default` 之类可能触发复制其他 Chrome profile 的名称。所有步骤复用同一会话名与路径；不要每条命令重建、close、清空 profile 或恢复 Cookie 文件。

使用包内固定调用入口，完整步骤见 [Agent Browser 固定配置接入](agent-browser.md)。由 AI 定位已经安装的工具入口并初始化一次，此后 get url、snapshot、真实 click 全部经 `scripts/browser-session.mjs`，不用每条命令自行拼 profile/headed/session。此可选入口使用 Node 标准库；已有 npm 安装通常已有 Node，不另加数据库或服务。

同一个 session 名不保证浏览器实例不变：启动选项变化可能导致工具重建浏览器。不要一条命令带 headed/profile、下一条只保留部分；不要混用裸 CLI、batch、新脚本与固定入口。重复 start 被拒绝后保留原页排查，不删除配置重来。

Ego 使用其当前技能文档中的任务空间/页面机制；原生工具使用其当前浏览器或窗口机制，不能套用上述 CLI 参数。工具不支持当前操作系统时走其他受支持路径，不强行运行另一个系统的安装脚本。

### 已有独立 Edge/Chrome 或临时驱动的迁移

先停止旧脚本的自动循环，保留已登录窗口和本人配置。若当前官方工具支持连接已有浏览器，且从本任务已有启动信息明确知道本人的本地 CDP 地址，可按当前工具文档连接该地址；连接前确认旧控制器已停止。同一浏览器只能有一个控制者。不要扫描端口、猜地址、连接他人的会话或开放远程调试到外网。

Agent Browser 当前文档支持 `connect <port|url>`，由 AI 使用已知的本地地址与独立会话名生成命令。连接后先读当前页，检查是否仍是本人的登录窗口；不附加 `--profile` 来创建另一个浏览器，不调用 Cookie 导入导出。没有可确认地址或工具不支持连接时，完成旧控制器停止后，按第 2 节建立标准接入并由本人登录，明确这是一次接入迁移。

浏览器出现非标准启动参数警告时，记录它是环境线索，不能据此认定页面故障原因；不继续加“隐身/反检测”参数，不移除验证提示来求通过。无需用户提供整个 profile 或认证数据。

## 3. 最小真实页面检查

按 `browser-session.md` 检查，不生成默认的多岗位评分校准报告：

1. 确认本人能看到真正受控的窗口；记录本轮工具实际返回的窗口/会话与页面标识、当前标题和URL。分两次独立调用读取仍为同一真实页面。这只证明连续性，不证明已经登录或可操作。
2. **先读当前完整可访问性快照或新鲜截图，排除覆盖列表的登录/验证码/风控弹层。** URL、头部用户名、消息数、底层 DOM 中的职位/JD 都不能单独证明已登录；DOM evaluate 可能读到遮层下面的旧内容。发现当前可交互的扫码/验证码登录控件或拦截指针的认证遮层，就保留页面交本人处理，不再试点卡片。本人完成后在原页重新检查遮层，再进入下一步。
3. 按本人配置选推荐入口、城市、薪资，核对实际生效的筛选。若入口不支持该条件，明确差异再决定，不暗改需求。
4. 只读检查至少一次卡片切换：新鲜快照/截图中当前职位与同页 JD 对应；所需字段可见。文本薪资乱码时用截图读可见数字，不调隐藏接口。
5. **以上各项都通过**才可按已确认条件和现有授权进入正常逐岗流程，不要求固定若干岗位的分析报告，也不反复让已授权用户确认。未授权则停在 review。

这里的“只读”是没有外发；选标签、筛选、切卡可以操作。页面读取成功、沟通按钮点击、平台满额分别是不同证据，不混在一起。

### 本人截图与工具页面不一致

先核对是否同一窗口，而不是反复要求登录或断言本人看的是普通 Chrome。Ego 本身也使用 Chromium 外观。报告应限定为“本轮工具选中的窗口，标题/URL为……，当前快照显示……”，不能外推为整个账号被风控。证据没有当前可见验证页或遮层时，只能说尚未确认，不能仅凭超时、空白或底层DOM推断风控。若选错窗口，承认选择错误；真正目标页存在验证时仍交本人处理，不能通过切换或新建会话绕过。

## 4. 按故障来源恢复

| 现象 | 恢复动作 |
| --- | --- |
| 下载超时、DNS、代理/证书报错 | 检查官方源网络，有限重试；可从同一 GitHub Release 下载 ZIP 并校验。不要改 BOSS 登录或关闭 TLS 校验 |
| 命令找不到、浏览器二进制缺失 | 按第 2 节只补缺项；重开客户端更新 PATH，不重写投递代码 |
| 权限弹窗 | 完成客户端/操作系统要求的授权；不模拟批准安全设置 |
| 客户端显示服务异常、模型额度/credits 错误 | 处理客户端服务或余额后在原任务续跑，保留浏览器；不靠刷新 BOSS、重登或新建投递任务解决 |
| BOSS 登录、验证码、风险提示 | 保留页面，交本人完成；恢复后重新读取当前页，不复制认证信息、不切工具规避 |
| 列表反复重建/空白 | 按 browser-session.md 的有限恢复处理；不连环刷新或循环重建浏览器 |
| 截图超时、AX 仍可读 | 不重复截图求通过；用当前完整 AX 判断遮层和字段。AX 不能可靠确认必需字段或安全状态则停止，截图不可用且薪资字形乱码时不能猜数 |
| 页面可见但 AX/DOM 不完整 | 用当前工具截图与可见操作；仍读不清的必要字段跳过，不从隐藏 API 填补 |
| 已点沟通后工具超时 | 不重试该岗；恢复当前列表并从下一岗继续，无法确定位置就停止外发 |

只把工具名称、系统、失败动作和脱敏后的错误摘要用于求助；不上传 profile、简历、聊天或整份日志。需要保存会话映射时仅放 private/，不含逐岗记录。任务正常运行时不周期性重做安装、环境诊断或全套页面验收。

## 5. 换电脑、换简历与更新

换电脑重新执行本页，浏览器登录由本人完成，不打包迁移认证信息。换简历只换 private/resume.md，条件与定时独立。更新技能下载新目录，继续使用本人既有工作区和原任务；读取新手册后恢复，不覆盖 private/ 或同时启动两套。

已有非本包配置时，先把本人明确要求映射到本包 private/policy.json，指出差异并由本人确认；迁移未完成只能 review，不混用两份规则，也不让模板覆盖原生产配置。技能目录与工作区分离时，在工作区自己的 .gitignore 中保留或补充 private/ 忽略规则，不覆盖原有规则；已有被跟踪的私人文件需要单独处理，gitignore 不会自动取消跟踪。

README 的一句话入口负责让当前 AI 完成这套准备，不是无条件保证所有机器都已通过。发布验证表分别标明代码测试、实际系统/工具、真实 BOSS 读取、外发和满额；未取得的证据不能写通过。
