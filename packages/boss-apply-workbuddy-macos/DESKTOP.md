# 使用 WorkBuddy 自带电脑操控

先检查当前任务实际提供的官方电脑操作工具，并读取其说明；工具名与参数以宿主返回为准。所需能力是观察目标浏览器窗口、截图或可访问性读取，以及鼠标键盘操作，不要求固定叫 `list_apps`、`get_app_state` 或 `ComputerUse`。技能下载成功不等于这些能力已接通。

宿主提供官方 `workbuddy-computer-use` 技能时，先读其当前说明。它是任务接口：`gui_list_windows` 选择已有窗口，`create_task` 执行一轮，返回需要继续时调用 `continue_task`；`read_task` 只查状态、不推进。按“读取当前 JD → 主模型匹配 → 合格后单次沟通”等目标委派，不把坐标或匹配决策交给工具。内部 GUI 任务结束后继续岗位循环；达到工具步数上限或错误时按官方说明释放槽位，再为确定尚未派发的步骤建立内部任务；已派发或结果不明的岗位不重试。内部 GUI 任务不是新建 WorkBuddy 对话、执行者或定时。关键结论按官方说明用真实画面核实，不以代理自报认定成功或满额，不进入聊天补核验。

已有可用能力时直接复用。缺工具时先通过应用正常“检查更新”，再查看“设置 → 智能体 → 电脑应用操控”的实际入口；未显示时，可用“专家·技能·连接器 → 技能 → 套件 → 添加市场”安装腾讯官方组件。由客户端读取[官方发布清单](https://static.workbuddy.cn/browser-computer-use/v1/computer-use/version.json)，按当前系统、架构及 `minAppVersion` 选择兼容项，按清单所在目录解析 `url`，核对下载 ZIP 的 `sha256` 后在正常市场入口添加，安装并启用 `computer-use@workbuddy-computer-use`。需要本人操作时给出已选定的官方地址和实际按钮，不让本人改配置文件。没有匹配项或正常入口时报告缺项，不修改隐藏开关或审批记录。

在“连接器 → 自定义连接器”的 MCP 管理中核对官方 `computer-use` 已连接且工具已启用，再以实际窗口读取和不外发操作验收；“已安装”本身不算接通。不信任或启用旧包的 `boss-desktop`，不反复让本人登录 BOSS。

官方安装、启用及 macOS 辅助功能、屏幕录制若需要新增访问，由本人在正常界面确认。不把“浏览器操控”扩展入口当作“电脑应用操控”。不自动安装第三方 MCP、浏览器、扩展或运行环境；不沿用旧包的第三方准备脚本和连接配置。已有本人明确选择的电脑工具正常可用时可以复用，按其实际说明执行。

在本人指定的已有浏览器窗口中，读取新鲜状态，操作一个不外发的控件，再观察对应变化；成功后继续 SKILL.md。macOS 默认系统 Safari，本人已指定其他已安装浏览器则沿用。不打开其它私人应用，不搬运登录状态。目标不明确才询问一次。

每次画面变化后重新观察；坐标或元素引用只取自当前工具最近一次状态。缺必要字段先从当前可见页面补足。窗口读取或工具调用失败属于控制问题，不能据此断言 BOSS 未登录、风控或当天满额。真实权限与网站验证由本人处理，已有授权范围内的普通定位错误自主恢复。

遵守本人费用上限；主模型标注免费不能代替电脑操控自身的费用提示。本人未授权额外费用时保留正常确认模式，不用“允许完全访问”跳过确认；出现额外积分提示时停在确认前。工具要求本人介入时转交实际提示，不盲目继续。

若官方能力暂不可用，保留原任务、个人资料和窗口，报告实际缺项及可见证据。只有本人明确选择其它接入方式后才评估替代方案，不在后台另建执行者或定时任务。
